# Sign In Page

Sign-in, account creation and a complete forgot-password flow, with a FastAPI backend.

Generated by Intent2Deploy AI from the request: "create a sign in page with both backend and frontend".

## Features

- Sign in and create an account, with validation as you type
- **Forgot password?** → request a 6-digit reset code → choose a new password (with a strength meter)
- Reset codes are single-use, expire after 15 minutes and lock after 5 wrong attempts
- Resetting a password signs the account out everywhere
- The API never reveals whether an email has an account

## Run

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8177
```

Open http://127.0.0.1:8177.

**Where it runs:** http://127.0.0.1:8177 — Intent2Deploy's staging preview serves this project on port 8177 (this project's own port), and the commands here use the same address. If you run it yourself while the preview is running, stop the preview first or use another port (e.g. `--port 8020`).

## Password reset emails

No email service is configured, so the app runs in **demo mode**: the reset code is shown on the page.
To send codes by email instead, deliver the code returned by `store.request_reset()` with your email
provider in `app/main.py` and start the app with `RESET_DEMO_MODE=0`.

## Notes

- Passwords are hashed with PBKDF2-SHA256 and a per-user salt; reset codes are stored only as SHA-256 hashes.
- Accounts, sessions and reset codes are kept in memory; add a database before production use.

## Docker

Build and run the image:

```bash
docker build -t sign-in-page-login .
docker run --rm -p 8177:8000 sign-in-page-login
```

Or with Docker Compose:

```bash
docker compose up --build
```

Then open http://127.0.0.1:8177
(health check: http://127.0.0.1:8177/health). If port 8177 is busy, change
the left side of the port mapping (e.g. `-p 8020:8000`).
This is the same address Intent2Deploy's staging preview uses for this project (port 8177); stop the preview first if you run the container yourself.

CI builds this image and checks the running container on every pull request and after each merge
into `staging` and `main` (`.github/workflows/docker.yml`).

## Database

Data is saved in SQLite at `DATABASE_PATH` (default `data/app.db`), so it survives restarts.
With Docker Compose it is kept in the `app-data` volume. Back it up by copying the file while the app is stopped.
